# FE 跨组件开发示例

在网易开发工作台的同一个本地基岩版测试工程中加入以下包。保持各包的清单和脚本目录层级。

| 组件 | 行为包 | 资源包 |
| --- | --- | --- |
| 工业模组通用前置库 | [FE](../behavior_packs/industrial_mod_lib) | 无 |
| 脉冲发电机 | [fe_source](source/behavior_packs/fe_source) | [fe_source](source/resource_packs/fe_source) |
| 测试电池 | [fe_receiver](receiver/behavior_packs/fe_receiver) | [fe_receiver](receiver/resource_packs/fe_receiver) |

两个示例各自依赖前置包。发电机通过 FE 查询下方方块的顶面能量端口，电池组件独立注册端口。创造模式可使用以下指令获得方块。

```mcfunction
/give @s iml_fe_source:generator
/give @s iml_fe_receiver:battery
```

1. 放置电池（铁块外观），将发电机（金块外观）紧贴放在电池正上方。查看工作台的服务端脚本日志，确认出现 `[FE receiver] Battery ports registered`。
2. 空手短按使用发电机。每次收到的使用事件最多发送 200 FE，日志显示实际送达和电池储量。持续按住可能产生多次事件。空手使用电池可查看当前储量。
3. 在充满前记下当前储量。保存退出并重新进入存档，直接使用电池核对电量。发电机由使用事件触发，重进期间电池电量应保持记录值。
4. 继续充至 1000 FE。再次使用发电机应记录送达 0 FE。将发电机移到电池侧面或下方后再使用，日志应提示发电机下方没有可接入的端口。
5. 在同一世界走远使区块卸载，再返回读取电池。确认储量与离开前一致，并尝试使用发电机验证端口可重新查询。

## 跨组件物品搬运验收

在同一 MC Studio 本地测试世界里启用以下三份 ZIP，停用相同 UUID 的旧版测试包。以下各节共用这组包。

- [IML 前置包 0.1.5](../mcstudio-test/acceptance/IML-library-chest-variants-0.1.5.zip)
- [发电机与搬运示例 0.1.11](../mcstudio-test/acceptance/IML-source-chest-variants-0.1.11.zip)
- [电池、储罐和导管 0.1.9](../mcstudio-test/acceptance/IML-receiver-item-conduit-0.1.9.zip)

用上面的 `/give` 命令拿到设备，摆两组空设备，每组发电机紧贴电池正上方。普通右键或空手潜行右键发电机进入面板。持方块潜行右键用于放置方块。在两种面板分别确认 E 和 Esc 能关闭。

| 操作 | 预期结果 |
| --- | --- |
| 第一组点 **Seed 10** | 发电机显示 `Apple x10 [marked]`，电池和恢复槽为空，模拟抽取后库存不变。 |
| 第一组点 **Send** | 显示 `Planned: 8 / Moved: 8`，发电机剩 2 个，电池有 8 个，两个库存都保留标记。 |
| 第一组再点 **Send** | 显示 `Planned: 0 / Moved: 0`，库存仍是 2 和 8。 |
| 第二组点 **Seed 10**，再点 **Partial test** | 显示 `Planned: 8 / Moved: 4`。发电机最终有 6 个，电池有 4 个，恢复槽为空，两边仍有标记。 |
| 保存退出，再进入同一个存档 | 重新打开两组发电机面板，核对数量、标记和恢复槽。右键电池查看对应的库存。 |

**Partial test** 查询电池的验收专用端口。空电池模拟可收 8 个，发电机实际提交完整的 8 个。电池写入 4 个并返回余量，搬运代码把这 4 个退回发电机。本地测试另覆盖了原槽拒绝退回时，带标记的余量进入恢复槽的情况。

记录实机结果、游戏版本和工作台版本。

## 原版单箱验收

将原版普通单箱放在空电池上，空发电机放在箱子正西侧，与箱子同高。发电机下方使用普通支撑方块。箱盖上方和箱子其他侧面留空。示例只搬运箱子的第一个槽位，也就是原版界面左上角那一格。

例如在同一测试区，从发电机坐标开始可按下面的位置摆放：

```mcfunction
/setblock 0 64 0 minecraft:stone
/setblock 1 64 0 iml_fe_receiver:battery
/setblock 1 65 0 minecraft:chest
/setblock 0 65 0 iml_fe_source:generator
```

| 操作 | 预期结果 |
| --- | --- |
| 发电机面板点 **Seed 10 → Preview** | 显示 `Preview: 10 item(s)`，发电机仍有 10 个，单箱仍为空。 |
| 发电机面板点 **Send** | 显示 `Planned: 10 / Moved: 10`。打开原版箱子，左上角有 10 个苹果，物品提示保留 `IML Transfer Sample`。 |
| 电池面板点 **Preview** 后再打开箱子 | 显示计划搬运 8 个。电池仍空，箱中仍有 10 个。 |
| 电池面板点 **Pull** 两次 | 第一次实际搬运 8 个，箱子剩 2 个、电池有 8 个，两处都保留标记。第二次显示 `Moved: 0`，箱子仍有 2 个。 |
| 保存退出，重进同一个存档 | 在原版箱子界面和电池面板分别核对 2 个和 8 个，确认物品提示及 `[marked]` 仍在。 |

可用一组新的设备检查失败与清空路径。先把一个圆石放进箱子的左上角，再从发电机发送带标记的苹果。预期搬运 0 个，圆石仍在，发电机仍有 10 个。然后取走圆石，将一个在铁砧重命名过的物品放进左上角。从空电池点 **Pull**，确认该箱槽清空，并在游戏聊天框输入 `imlitem read X Y Z`（电池坐标，无需斜杠），核对服务端日志中物品的名称数据。

## 原版双箱搬运验收

以实测的双箱坐标为例，两半分别位于 `-1 68 0` 和 `0 68 0`。将发电机放在 `-2 68 0`，电池放在 `0 67 0`，双箱的上方留空。使用新设备，或先取走双箱第四排左侧的物品并确认电池为空。

1. 在发电机面板点 **Seed 10**。在聊天框输入 `imlmove preview -2 68 0 27`，无需斜杠。预期计划搬运 10 个，双箱第 27 号槽仍为空。
2. 输入 `imlmove send -2 68 0 27`。预期发电机剩 0 个，双箱第 27 号槽有 10 个带标记的苹果。
3. 输入 `imlmove pull 0 67 0 27`。电池从另一半访问同一格，预期电池收到 8 个，双箱第 27 号槽剩 2 个。再次执行时搬运量为 0。
4. 保存退出并重进，双箱仍有 2 个，电池仍有 8 个。用测试物品验证拆分，再查询剩下的单箱，预期恢复 27 槽。

面板中的 **Send** 和 **Pull** 默认使用第 0 号槽，聊天命令可指定第 27 至 53 号槽。

## 原版双箱槽位探针

加载上面的三个包。在测试世界摆一个原版双箱，打开箱子，在第一排左上角放 1 个圆石，在第四排左侧放 2 个苹果，其余槽位留空。把两个方块坐标记为 A 和 B。

在聊天框输入 `imlchestprobe X Y Z`，填 A 的坐标，开头无需斜杠。命令记录两半的方块 ID（`block`）、配对坐标（`paired`）、引擎槽数（`size`）、IML 槽数（`iml_slots`）和非空槽位。也可以对单箱、陷阱箱和铜箱运行。若要核对拆分，用测试物品，移除其中一半后对剩下的箱子再运行一次。探针只读取库存。

## 陷阱箱与铜箱验收

启用上面的三个新版包，停用同 UUID 的旧包。箱子适配覆盖普通箱、陷阱箱，以及以下 8 种铜箱。表中的 ID 省略了 `minecraft:`。

| 氧化阶段 | 未涂蜡 | 涂蜡 |
| --- | --- | --- |
| 初始 | `copper_chest` | `waxed_copper_chest` |
| 斑驳 | `exposed_copper_chest` | `waxed_exposed_copper_chest` |
| 锈蚀 | `weathered_copper_chest` | `waxed_weathered_copper_chest` |
| 氧化 | `oxidized_copper_chest` | `waxed_oxidized_copper_chest` |

1. **单箱收发。** 按[单箱摆法](#原版单箱验收)，依次使用普通箱、陷阱箱和 8 种铜箱。每次用空的箱子和电池，发电机点 **Seed 10 → Preview → Send**，电池点 **Preview → Pull**。预期预览不改库存，发电机送出 10 个，电池取走 8 个，箱子剩 2 个且仍有标记。
2. **单双箱切换。** 各摆一组普通双箱、双陷阱箱和同变种铜双箱，按[双箱搬运步骤](#原版双箱搬运验收)从一半向槽 27 送入 10 个，再从另一半取走 8 个。两半探针都应报告 `size=54 iml_slots=54`，同一槽最终剩 2 个。移除一半后，剩下的箱子应恢复 `size=27 iml_slots=27`。
3. **铜箱变种切换。** 往一个未涂蜡铜单箱送入 10 个，关闭面板后用蜜脾涂蜡。右键下方的空电池点 **Preview**，应仍计划取出 8 个。用斧头刮蜡后，重新打开电池面板点 **Pull**，核对铜箱剩 2 个且保留标记。
4. **回归。** 复跑[木桶与潜影盒](#木桶与潜影盒验收)的 **5 + 3** 汇流、拒绝套盒和整盒内容保留。

如果某个版本或变种无物品端口、收发失败，或两半看到了不同的槽号，记录游戏版本、MC Studio 版本以及该箱的 `[IML chest probe]` 日志。IML 在配对坐标不互指或双方容量不一致时会拒绝打开双箱端口。

## 流体验收

加载上面的三个包。在创造模式领取并放置可独立使用的 **Fluid Tank**。每个储罐容量为 1000 mB，顶面注入，底面抽取。

```mcfunction
/give @s iml_fe_receiver:tank 3
/give @s iml_fe_source:generator
```

把三个空罐垂直叠放，发电机紧贴在最上面的罐上方。右键发电机打开 **Generator Fluids**，右键任意罐打开 **Fluid Tank**。下表按顺序使用同一组设备。

| 操作 | 预期结果 |
| --- | --- |
| 发电机点 **Load Water → Preview** | 装入 1500 mB 水，显示 `Preview: 1000 mB`，最上面的罐仍为空。 |
| 发电机点 **Send** 两次 | 第一次送出 1000 mB，发电机剩 500 mB，最上面的罐满。第二次送出 0 mB。 |
| 最上面的罐点 **Send Down**，再从发电机点 **Send** | 中间的罐收到 1000 mB 水，最上面的罐再次收到 500 mB，发电机变空。 |
| 发电机点 **Load Lava → Send** | 发电机保持 1500 mB 岩浆，最上面的罐保持 500 mB 水，送出量为 0。 |
| 中间的罐点 **Send Down**，再从最上面的罐点 **Send Down** | 最下面保留 1000 mB 水，中间保留 500 mB 水，最上面的罐变空。 |
| 发电机点 **Send**，保存退出并重进 | 最上面的罐装有 1000 mB 岩浆，发电机剩 500 mB 岩浆。重进时水和岩浆的类型、数量均可从面板核对。 |

若面板打不开，可在聊天框输入 `imlpanel X Y Z`，填发电机或储罐坐标，无需斜杠。

## 一对多物品搬运验收

领取发电机、电池和 `/give @s iml_fe_receiver:item_conduit`。从下往上紧贴摆放空电池、**Item Conduit** 和发电机，把空的原版普通单箱摆在导管正东侧，与导管同高，并保持箱盖上方为空。右键发电机打开 **Batch Item Transfer**。

| 操作 | 预期结果 |
| --- | --- |
| 点 **Seed 10 → Preview** | 显示 `Down: 8 planned`、`East: 2 planned`。发电机仍有 10 个标记苹果，打开电池和箱子检查两者仍为空。 |
| 点 **Run Round** | 显示 `Down: 8 moved / 8 planned`、`East: 2 moved / 2 planned`。发电机和导管恢复槽均为 0，电池收到 8 个，箱子左上角有 2 个并保留 `IML Transfer Sample` 提示。 |
| 再点 **Run Round**，保存退出后重进 | 两路送达量均为 0。重进后核对发电机为 0、电池为 8、箱子为 2。 |
| 取走东侧箱子，再打开面板 | 显示 `East: Disconnected`。电池仍满时重新装料并执行一轮，10 个苹果应全部留在发电机。 |

要验证 4 和 6 的分流，先在另一组空电池上直接摆一台发电机，点 **Seed 10 → Partial test**，让电池已有 4 个标记苹果。移走该发电机，在原处摆导管、上方摆新的发电机、东侧摆空箱。新发电机装料后，预览和实际搬运均应为 **Down 4 / East 6**，电池最终 8 个、箱子 6 个。

每次 **Run Round** 检查最多 8 个不同的目标槽，最多搬运 10 个物品。执行时先尝试向下，再尝试向东。验收时记录游戏版本、工作台版本和两路实际搬运数量。

## 多对一物品搬运验收

导入上面的三个包并停用同 UUID 的旧包。把 **Item Conduit** 紧贴放在空电池正上方，在导管正西和正东各放一个原版普通单箱，两个箱子与导管同高。看坐标时，西侧是 X 减 1，东侧是 X 加 1。箱盖上方留空，右键导管打开 **Item Gathering**。确认 E 与 Esc 均可关闭面板。持方块潜行右键时应照常放置方块。

| 操作 | 预期结果 |
| --- | --- |
| 两个箱子左上角各放 5 个普通苹果，点 **Preview** | 显示 `West: 5 planned`、`East: 3 planned`。打开箱子和电池，两个箱子仍各有 5 个，电池仍空。 |
| 点 **Run Round** | 显示 `West: 5 moved / 5 planned`、`East: 3 moved / 3 planned`。西箱空、东箱剩 2 个，电池有 8 个，恢复槽为 0。 |
| 电池满时再点 **Run Round** | 两路均搬运 0 个，东箱仍有 2 个。保存退出并重进，确认数量保持不变。 |
| 另摆一组空设备，西箱左上角放 5 个苹果，东箱左上角放 5 个圆石 | **Preview** 和 **Run Round** 均显示西侧 5 个、东侧 0 个。电池收到 5 个苹果，圆石全留在东箱。 |

每轮只处理两个箱子的左上角槽位，固定先西后东。右键电池可在 **Battery Inventory** 核对数量。若面板打不开，可在聊天框输入 `imlpanel X Y Z`，填导管坐标，无需斜杠。

## 木桶与潜影盒验收

复用上面的导管摆法。每次用空的目标，向输入容器的左上角放测试物品，再右键导管打开 **Item Gathering**。导管下方是原版容器时，面板用 **Output** 显示目标槽的数量。

| 场景 | 操作与预期 |
| --- | --- |
| 西侧木桶、东侧染色潜影盒、下方空电池 | 两边各放 5 个普通苹果。**Preview** 显示西 5、东 3，库存不变。**Run Round** 后木桶空、潜影盒剩 2 个、电池收到 8 个、恢复槽为 0。 |
| 西侧木桶、下方空潜影盒 | 东侧留空，木桶放 3 个苹果。**Preview** 和 **Run Round** 均应显示西侧 3 个。面板应显示 `Output: 3`。若导管挡住潜影盒开盖，在核对恢复槽为 0 后暂时移开导管，打开潜影盒确认左上角有 3 个苹果。 |
| 拒绝套盒 | 西侧普通箱的左上角放 1 个潜影盒物品，导管下方摆空潜影盒。**Preview** 与 **Run Round** 都应显示西侧 0 个，潜影盒物品仍在西箱。 |
| 搬运装有物品的潜影盒 | 在一只测试潜影盒里放两种物品，记下数量和位置。挖下盒子后放进西侧普通箱的左上角，下方换成空木桶。**Run Round** 应送达 1 个。保存重进后，从木桶取出这只盒子并重新放下，核对盒内物品、数量和槽位。 |

最后用普通箱复跑一次 **5 + 3**，确认既有路径正常。若某个颜色的潜影盒显示 `Disconnected`，记录颜色以及它所在的西侧、东侧或下方。
