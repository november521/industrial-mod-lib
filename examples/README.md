# FE 跨组件开发示例

在网易开发工作台的同一个本地基岩版测试工程中加入以下包。保持各包的清单和脚本目录层级。

| 组件 | 行为包 | 资源包 |
| --- | --- | --- |
| 工业模组通用前置库 | [FE](../behavior_packs/industrial_mod_lib) | 无 |
| 脉冲发电机 | [fe_source](source/behavior_packs/fe_source) | [fe_source](source/resource_packs/fe_source) |
| 测试电池 | [fe_receiver](receiver/behavior_packs/fe_receiver) | [fe_receiver](receiver/resource_packs/fe_receiver) |

两个示例各自依赖前置包。发电机通过 FE 查询下方方块的顶面能量端口，电池组件独立注册端口。创造模式可使用以下指令获得方块。

```mcfunction
/give @s iml_fe_source:generator
/give @s iml_fe_receiver:battery
```

1. 放置电池（铁块外观），将发电机（金块外观）紧贴放在电池正上方。查看工作台的服务端脚本日志，确认出现 `[FE receiver] Battery ports registered`。
2. 空手短按使用发电机。每次收到的使用事件最多发送 200 FE，日志显示实际送达和电池储量。持续按住可能产生多次事件。空手使用电池可查看当前储量。
3. 在充满前记下当前储量。保存退出并重新进入存档，直接使用电池核对电量。发电机由使用事件触发，重进期间电池电量应保持记录值。
4. 继续充至 1000 FE。再次使用发电机应记录送达 0 FE。将发电机移到电池侧面或下方后再使用，日志应提示发电机下方没有可接入的端口。
5. 在同一世界走远使区块卸载，再返回读取电池。确认储量与离开前一致，并尝试使用发电机验证端口可重新查询。

## 跨组件物品搬运验收

在同一 MC Studio 本地测试世界里启用以下三份 ZIP，停用相同 UUID 的旧版测试包。这组包也用于下面的单箱验收。

- [IML 前置包 0.1.2](../mcstudio-test/acceptance/IML-library-double-chest-0.1.2.zip)
- [发电机 0.1.6](../mcstudio-test/acceptance/IML-source-double-chest-0.1.6.zip)
- [电池 0.1.5](../mcstudio-test/acceptance/IML-receiver-double-chest-0.1.5.zip)

用上面的 `/give` 命令拿到设备，摆两组空设备，每组发电机紧贴电池正上方。普通右键或空手潜行右键发电机进入面板。持方块潜行右键用于放置方块。在两种面板分别确认 E 和 Esc 能关闭。

| 操作 | 预期结果 |
| --- | --- |
| 第一组点 **Seed 10** | 发电机显示 `Apple x10 [marked]`，电池和恢复槽为空，模拟抽取后库存不变。 |
| 第一组点 **Send** | 显示 `Planned: 8 / Moved: 8`，发电机剩 2 个，电池有 8 个，两个库存都保留标记。 |
| 第一组再点 **Send** | 显示 `Planned: 0 / Moved: 0`，库存仍是 2 和 8。 |
| 第二组点 **Seed 10**，再点 **Partial test** | 显示 `Planned: 8 / Moved: 4`。发电机最终有 6 个，电池有 4 个，恢复槽为空，两边仍有标记。 |
| 保存退出，再进入同一个存档 | 重新打开两组发电机面板，核对数量、标记和恢复槽。右键电池查看对应的库存。 |

**Partial test** 查询电池的验收专用端口。空电池模拟可收 8 个，发电机实际提交完整的 8 个。电池写入 4 个并返回余量，搬运代码把这 4 个退回发电机。本地测试另覆盖了原槽拒绝退回时，带标记的余量进入恢复槽的情况。

## 原版单箱验收

将原版普通单箱放在空电池上，空发电机放在箱子正西侧，与箱子同高。发电机下方使用普通支撑方块。箱盖上方和箱子其他侧面留空。示例只搬运箱子的第一个槽位，也就是原版界面左上角那一格。

例如在同一测试区，从发电机坐标开始可按下面的位置摆放：

```mcfunction
/setblock 0 64 0 minecraft:stone
/setblock 1 64 0 iml_fe_receiver:battery
/setblock 1 65 0 minecraft:chest
/setblock 0 65 0 iml_fe_source:generator
```

| 操作 | 预期结果 |
| --- | --- |
| 发电机面板点 **Seed 10 → Preview** | 显示 `Preview: 10 item(s)`，发电机仍有 10 个，单箱仍为空。 |
| 发电机面板点 **Send** | 显示 `Planned: 10 / Moved: 10`。打开原版箱子，左上角有 10 个苹果，物品提示保留 `IML Transfer Sample`。 |
| 电池面板点 **Preview** 后再打开箱子 | 显示计划搬运 8 个。电池仍空，箱中仍有 10 个。 |
| 电池面板点 **Pull** 两次 | 第一次实际搬运 8 个，箱子剩 2 个、电池有 8 个，两处都保留标记。第二次显示 `Moved: 0`，箱子仍有 2 个。 |
| 保存退出，重进同一个存档 | 在原版箱子界面和电池面板分别核对 2 个和 8 个，确认物品提示及 `[marked]` 仍在。 |

可用一组新的设备检查失败与清空路径。先把一个圆石放进箱子的左上角，再从发电机发送带标记的苹果。预期搬运 0 个，圆石仍在，发电机仍有 10 个。然后取走圆石，将一个在铁砧重命名过的物品放进左上角。从空电池点 **Pull**，确认该箱槽清空，并在游戏聊天框输入 `imlitem read X Y Z`（电池坐标，无需斜杠），核对服务端日志中物品的名称数据。

## 原版双箱搬运验收

以实测的双箱坐标为例，两半分别位于 `-1 68 0` 和 `0 68 0`。将发电机放在 `-2 68 0`，电池放在 `0 67 0`，双箱的上方留空。使用新设备，或先取走双箱第四排左侧的物品并确认电池为空。

1. 在发电机面板点 **Seed 10**。在聊天框输入 `imlmove preview -2 68 0 27`，无需斜杠。预期计划搬运 10 个，双箱第 27 号槽仍为空。
2. 输入 `imlmove send -2 68 0 27`。预期发电机剩 0 个，双箱第 27 号槽有 10 个带标记的苹果。
3. 输入 `imlmove pull 0 67 0 27`。电池从另一半访问同一格，预期电池收到 8 个，双箱第 27 号槽剩 2 个。再次执行时搬运量为 0。
4. 保存退出并重进，双箱仍有 2 个，电池仍有 8 个。用测试物品验证拆分，再查询剩下的单箱，预期恢复 27 槽。

面板中的 **Send** 和 **Pull** 默认使用第 0 号槽，聊天命令可指定第 27 至 53 号槽。

## 原版双箱槽位探针

加载上面的三个包。在测试世界摆一个原版双箱，打开箱子，在第一排左上角放 1 个圆石，在第四排左侧放 2 个苹果，其余槽位留空。把两个方块坐标记为 A 和 B。

在聊天框输入 `imlchestprobe X Y Z`，填 A 的坐标，开头无需斜杠。命令读取两半报告的容量和非空槽位。把服务端日志中的两行 `[IML chest probe]` 发回来。若方便，移除其中一半并对剩下的单箱再运行一次，记录拆分后的容量和槽号。探针只读箱内物品，拆分请使用测试物品。
